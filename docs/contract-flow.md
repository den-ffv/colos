# Contract Flow — COLOS CRM

## Загальна схема

```
DRAFT → AWAITING_SIGNATURE → AWAITING_PAYMENT → IN_PROGRESS → COMPLETED
                ↓
           REJECTED (клієнт не підтвердив / код прострочений)
```

---

## Детальний Flow

### Крок 1 — Менеджер створює договір (DRAFT)

**Хто:** MANAGER, ADMIN

Менеджер заповнює форму договору:
- Клієнт (з бази)
- Маршрут (адреса завантаження / розвантаження)
- Вантаж (тип, вага, кількість)
- Дата виконання
- Ціна для клієнта
- Призначений водій (необов'язково на цьому кроці)
- Нотатки / умови

Статус: `DRAFT`

---

### Крок 2 — Відправка клієнту на підписання

**Хто:** MANAGER (натискає "Відправити клієнту")

- Система генерує **6-значний OTP-код підтвердження** (TTL: 48 год)
- На email клієнта відправляється:
  - PDF договору як вкладення
  - Код підтвердження (або посилання з вбудованим кодом)
- Статус → `AWAITING_SIGNATURE`
- Фіксується `sent_at`

> Email містить: "Для підписання договору №CONTR-2026-0001 введіть код підтвердження: **847293**"

---

### Крок 3 — Клієнт підтверджує (вводить код)

**Хто:** Клієнт (через email або окрему публічну сторінку)

**Варіант A — успішне підписання:**
- Клієнт вводить код → система перевіряє
- Статус → `AWAITING_PAYMENT`
- Фіксується `signed_at`
- Автоматично генерується **PDF рахунку на оплату** і відправляється на той же email клієнта
- Менеджер отримує сповіщення: "Договір CONTR-2026-0001 підписано клієнтом"

**Варіант B — відхилення / прострочений код:**
- Клієнт не відповів протягом 48 год → статус → `REJECTED`
- Менеджер може скинути код і відправити повторно (новий DRAFT → знову Крок 2)

---

### Крок 4 — Підтвердження оплати (MANAGER)

**Хто:** MANAGER, ACCOUNTANT

- Клієнт оплачує рахунок і **повідомляє менеджера** (телефон, email, месенджер)
- Менеджер у системі відкриває договір і натискає **"Підтвердити оплату"**
  - Вказує суму оплати та дату
- Статус → `IN_PROGRESS`
- Фіксується `paid_at`
- Менеджер призначає водія на виконання (якщо ще не призначено)
- Водій отримує сповіщення через Socket.io: "Вам призначено новий рейс"

---

### Крок 5 — Виконання (DRIVER)

**Хто:** Водій (через Driver Portal)

- Водій бачить договір у своєму портальному списку (статус `IN_PROGRESS`)
- Водій переглядає деталі: маршрут, адреса завантаження, клієнт
- Водій виїжджає, прибуває до адреси **доставки** і натискає **"Прибув"**
  - Фіксується `arrived_at`, геолокація (якщо дозволено)
- Статус → `COMPLETED`
- Менеджер отримує сповіщення: "Рейс CONTR-2026-0001 виконано"

> Водій може **тільки читати** договір і **натискати "Прибув"** — жодних інших змін він не робить.

---

## Статусна машина

| Статус | Хто переводить | Наступні стани |
|--------|---------------|----------------|
| `DRAFT` | Менеджер | `AWAITING_SIGNATURE` |
| `AWAITING_SIGNATURE` | Система (після підтвердження коду) | `AWAITING_PAYMENT`, `REJECTED` |
| `AWAITING_PAYMENT` | Менеджер (ручне підтвердження) | `IN_PROGRESS` |
| `IN_PROGRESS` | Водій (кнопка "Прибув") | `COMPLETED` |
| `COMPLETED` | — | — |
| `REJECTED` | Менеджер (повторна відправка) | `DRAFT` |

## Схема даних (Prisma)

```prisma
enum ContractStatus {
  DRAFT
  AWAITING_SIGNATURE
  AWAITING_PAYMENT
  IN_PROGRESS
  COMPLETED
  REJECTED
}

model Contract {
  id               String         @id @default(uuid())
  contract_number  String         @unique   // CONTR-2026-0001

  status           ContractStatus @default(DRAFT)

  // Контрагент
  client_id        String
  client           Client         @relation(fields: [client_id], references: [id])

  // Маршрут і вантаж (або прив'язка до Order)
  pickup_address   String
  delivery_address String
  pickup_date      DateTime
  product_type     String?
  weight           Float?
  client_price     Float

  // Виконавець
  driver_id        String?
  driver           Driver?        @relation(fields: [driver_id], references: [id])

  // Підписання через OTP
  otp_code         String?        // хеш OTP-коду
  otp_expires_at   DateTime?

  // Оплата
  paid_amount      Float?
  paid_at          DateTime?

  // Таймстемпи подій
  sent_at          DateTime?
  signed_at        DateTime?
  arrived_at       DateTime?

  // Відхилення
  rejected_reason  String?

  notes            String?

  // Відповідальний менеджер
  manager_id       String
  manager          User           @relation(fields: [manager_id], references: [id])

  company_id       String
  company          Company        @relation(fields: [company_id], references: [id])
  created_at       DateTime       @default(now())
  updated_at       DateTime       @updatedAt

  @@map("contracts")
}
```

## Що потрібно реалізувати

| Компонент | Деталі |
|-----------|--------|
| Prisma модель `Contract` | Додати в `schema.prisma`, міграція |
| `contracts.routes.ts` | CRUD + POST `/send` + POST `/confirm-otp` + POST `/confirm-payment` + POST `/arrive` |
| Email сервіс | `nodemailer` або `resend` — відправка OTP і рахунку |
| OTP генерація | 6 цифр, bcrypt-хеш у БД, TTL 48 год |
| PDF рахунку | Новий метод `generateInvoicePdf` в `pdf.service.ts` |
| Driver Portal | Вкладка "Мої рейси" — список + кнопка "Прибув" |
| Socket.io події | `contract:signed`, `contract:paid`, `contract:completed` |
| Публічна сторінка | `/confirm/:token` — без авторизації, для клієнта |
